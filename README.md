# 跑步机跑姿分析 Web Demo

本项目按 `方案.md` 实现视频/摄像头 → RTMPose → 步态事件 → 指标与报告的流程，适合固定机位拍摄的单人侧面跑步画面。它是可在浏览器中使用和部署的演示项目，分析结果仅供运动观察。

## 本地启动

推荐 Python 3.10 或 3.11，并使用独立虚拟环境。本地还需安装 FFmpeg（macOS 可运行 `brew install ffmpeg`）；Docker 镜像会自动安装：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

程序会自动打开 `http://127.0.0.1:8000`。如果是在无桌面的服务器上启动，使用 `python app.py --no-browser`，再自行打开该地址。

界面提供三种模式：

- **视频分析**：上传 MP4、MOV 或 AVI 后，在原视频上逐帧叠加所选模型的骨架。播放或拖动进度条时，膝/髋关节曲线、游标和当前数值同步更新。单次上传上限为 2 GB。
- **实时摄像头**：经浏览器授权后，在摄像头画面上实时绘制骨架，并连续绘制左右膝关节角度曲线。
- **分析历史**：查看已完成的指标和报告；原视频仍存在时，可以创建一次新的重新分析，不覆盖旧结果。

### 姿态模型

视频分析、实时摄像头和历史重新分析均使用 **RTMPose**。采用 RTMPose-s + YOLOX-tiny，通过 RTMLib / ONNX Runtime 在 CPU 上运行，输出 COCO 17 关键点；多人画面取身体关键点平均置信度最高者。重新分析旧记录时也使用 RTMPose，并创建独立结果。

已有环境先运行 `python -m pip install -r requirements.txt`。首次使用时会联网下载权重，缓存位于 `~/.cache/rtmlib/`；Docker 中缓存存于数据卷。

分析接口保留统一的 33 槽位，实际填入 17 个二维关键点，其余为空。模型没有脚跟、脚尖和手指细节，骨架只绘制实际检测到的关节。轨迹统一使用左右脚踝，膝/髋角度与步态分析也基于实际关节计算。深度列 `z=0` 仅为接口占位，不表示真实深度。

### VideoPose3D 跑步三维骨架

当前默认平面实验为版本 3：每一帧直接使用原始右髋减左髋的单位向量作法向，分别通过原始左右髋建立两个平行平面，只投影对应膝踝，不移动髋节点、不使用肩线或地面调整法向。双髋缺失/重合帧不输出约束腿。平面随髋连线逐帧变化，保证垂直于当帧髋连线，不保证垂直于地面。下述版本 1/2 为历史实验，旧记录需重新分析。导出逐帧法向和最大投影残差。

新分析默认提供“双髋平面约束 · 侧面轨迹”周期图，与原始二维图共用逐周期曲线、平均曲线、周期列表和视频同步定位。每帧在腿部活动平面内建立前后/向上轴，髋中心为原点，输出 `plane_side_keypoints`、JSON `plane_sagittal` 与 `foot_motion_plane`。周期边界沿用二维脚踝事件，纵坐标为相对髋部高度，不代表离地高度；平面随髋转动可能影响曲线，不能解释为固定世界侧面。保留原始二维及站立标定选项。

新增肩髋平均轴硬平面约束实验：分别归一化右肩减左肩、右髋减左髋方向，按时间平均并等权融合，排除偏离初始方向超过 60° 的采样。两类采样各至少 10 帧，方向退化时不启用。左右膝、踝投影到分别经过对应髋关节、以平均左右轴为法向的两个平行平面；方向固定，平面随髋平移。默认显示约束版，开关可对比未约束版，原始三维踝轨迹同时可查看。硬投影会改变骨长与关节角度，不代表重力或真实地面，站立标定侧面轨迹仍保留独立含义。NPZ/JSON 保存约束前后数组与位移、骨长变化指标。

平面约束版本 2 将平均左右轴投影到显示/标定地面内，确保腿平面法向与地面法向正交。双髋以保持髋中心与原始髋宽为条件，对齐到这个固定水平左右轴；再投影左右膝踝。因此活动平面严格垂直于修正后的髋连线和参考地面。它不保证垂直于每帧原始髋线，原始髋线本身存在倾斜误差；未标定时 +Y 地面法向仍是显示参考。版本 1 历史记录须重新分析，前端不再启用旧约束。元数据保存测得轴、水平轴、地面法向及最大平面残差。

已有输出可运行 `python plane_case.py --input output/experiments/coordinate-quality/real/skeleton3d.npz --output output/leg-plane-case` 生成对比图片、轨迹及约束数组，无需重新训练。

每次上传视频或重新分析自动运行 **RTMPose COCO 17 点 → VideoPose3D → 17 点三维骨架**，按模型要求重采样到 50 Hz，再还原到原视频时间戳。无需站立参考或身高标定。

三维骨架与视频同步，支持旋转和缩放。使用 Human3.6M 17 点骨架，以双髋中点为原点，轨迹使用左右脚踝。二维分数仅用于可见性筛选，不是三维置信度。

视频与三维骨架同步显示。提供站立标定后，后端估计整段固定旋转矩阵，X 为跑步方向、Y 向上、Z 横向。旋转不会扶直跑步躯干或修改骨长。骨架保持髋中心原点，踝轨迹使用髋中心正下方估计地面原点，保留髋部起伏；两套视图使用同一标定和尺度。未标定或标定失败时显示原始相机空间骨架、隐藏校正曲线。前端不再使用下肢 PCA 猜测侧面。

当前输出版本为 5。坐标系为 `camera_pelvis_relative` 或标定后的 `world_pelvis_relative`，仍是单目弱透视估计，不保证真实深度或米制测量。旧记录需重新分析；站立参考与跑步必须同机位、无变焦。

未标定时，骨架默认使用全片固定的显示旋转，将平均三维躯干方向对齐到视频二维肩髋方向，去除显示中的整体倾斜；保留二维中可见的前倾。此过程假设显示参考的躯干深度分量为零，仅供查看，不是相机标定，不生成校正轨迹。按钮可切换原始相机朝向；NPZ 保留原始显示坐标和显示旋转矩阵。标定后的骨架不再执行这项近似对齐。

内部二维缺口仅在两侧有效观测间隔不超过 0.1 秒时插值。较长缺口和边界缺失使用最近观测作为模型计算填充，单独记录，不能视作检测；缺口前后各 2.42 秒（模型半窗口）不参与校正。校正姿态仅在连续有效区段以 50 Hz、9 帧、二阶 Savitzky–Golay 平滑，不跨遮挡。不会自动交换左右标签、强制对称或把脚踝贴地。

质量诊断包含骨长 CV、左右腿长差、弱透视重投影误差、疑似交换、时序支持比例及平滑变化。重投影比较对应肩/髋/膝/踝点并拟合全片统一尺度；小误差不证明深度准确。`skeleton3d.npz` 保存原始、平滑、仅旋转和旋转加平滑的数组，以及旋转矩阵和时序有效标记；`skeleton3d.json` 保存后端校正轨迹和质量诊断。

VideoPose3D 官方 COCO 权重约 68 MB，下载时校验 SHA256，缓存于数据目录 `models/pretrained_h36m_detectron_coco.bin`。CPU 推理，复用已有环境，无需训练。三维失败时保留二维分析。站立参考校正与三维回放复用未缩放的三维预测。

输出 `skeleton3d.json`、`skeleton3d.npz`，与站立参考校正的 `pose3d.npz` 分开保存，`metrics.json` 记录模型与可用状态。VideoPose3D 网络代码遵循 CC BY-NC 4.0 许可证。

### 斜视角的侧面轨迹估计

上传表单展开“斜视角校正”，勾选启用，输入身高与画面中的跑步方向。选择当前视频中的 **1–10 秒直立站稳片段**（建议 3 秒），或上传同一机位、同一跑步位置的站立短视频。两段视频必须画面比例相同，相机不能移动或变焦，跑台应水平。暂停在片段内的清晰画面，点击“用当前画面标记”，依次在快照上标记头顶与双脚支撑位置中点（跑台表面）。标记后再开始分析。

历史页的“标定 / 侧面校正”可为保留的原视频设置或更新标定；“重新分析”自动继承原有标定和参考视频，并新建结果。关闭校正后重新分析仍生成二维分析和独立三维骨架，不计算侧面校正轨迹。

检测仍使用 RTMPose。新增 VideoPose3D 的 COCO 输入时序模型估计相对髋部的三维骨架，按实际时间戳重采样至 50 Hz，再还原到原视频帧。首次校正需下载约 68 MB 权重，缓存在数据目录 `models/` 下并校验 SHA256；已有环境运行 `python -m pip install -r requirements.txt`，Docker 使用 `docker compose up -d --build` 更新。

结果页可切换“原始二维轨迹”和“估计的侧面轨迹”，两种轨迹各自计算周期平均与偏差。校正图的原点是双髋中点沿估计竖直方向在跑台平面的投影；横轴向跑步方向为正，纵轴为估计的脚踝离地高度，按三维腿长归一化。坐标系由直立参考固定，避免随跑步摆动逐帧转动；脚踝中心高于脚底，支撑时不强制设为零。髋部上下起伏由固定机位下的二维位置变化和弱透视近似估计，三维模型本身不提供绝对人体位置。身高辅助尺度参考，不能单独恢复拍摄角度或真实深度。

过于接近正面/背面、明显身体转向、站立骨架或标记退化时，界面说明校正不可用并保留原始分析。校正属于单目模型和弱透视假设下的近似，不是真实三维测量；膝/髋关节角度仍为二维估计。实时摄像头暂不进行三维校正。

新增输出：

- `view_correction.json`：标定、坐标轴、估计拍摄角度、有效帧比例及失败原因。
- `pose3d.npz`：成功校正时保存 Human3.6M 顺序的三维骨架、相对髋中点的地面原点、髋部高度及逐帧左右脚踝轨迹与有效标记。三维位置为估计值，带 `_m` 的字段也不代表经过相机标定的真实米制测量。
- `timeline.json` / `metrics.json`：原始 `foot_motion` 保留，另提供 `foot_motion_corrected` 与 `view_correction`；失败或未启用时没有校正曲线。
- PDF 新增原始与估计侧面平均轨迹对照，注明单目估计。

命令行可通过 `--calibration calibration.json --reference-video standing.mp4` 传入相同标定：

```json
{"height_cm": 170, "source": "reference", "start_seconds": 0, "end_seconds": 3, "marker_seconds": 1.5, "head": [0.5, 0.1], "ground": [0.5, 0.9], "facing": "right"}
```

参考点使用画面宽高归一化坐标；`source: "video"` 表示从跑步视频取站立片段，无需 `--reference-video`。

三维模型架构来自 [VideoPose3D](https://github.com/facebookresearch/VideoPose3D)，副本与原许可证保存在 `pose/vendor/`；该部分采用 **CC BY-NC 4.0**，适用于非商业研究/演示，商业使用需要另行取得许可。

### 脚踝轨迹周期与稳定性

轨迹图统一使用**左脚踝和右脚踝**；导出的 `timeline.json` 与 `metrics.json` 中，`foot_motion.left/right.landmark` 和 `landmark_index` 注明节点名称与统一索引（27、28）。每侧以**相邻两次同侧着地**作为一个周期。着地检测使用脚踝离地高度的摆动峰及向下阈值穿越，减少画面上下漂移导致的漏检，但左右周期数不强制相等：视频起止可能截断周期，遮挡或姿态识别失败也可能造成漏检。脚踝位置相对可见髋部的中点计算，横坐标按视频宽高比修正，再除以大腿和小腿中位长度之和；左右图使用相同的坐标范围，纵轴向上为正。每个可绘制周期按时间/周期相位插值为 64 个点；每侧首尾各排除一个周期，中间周期通过可见度与离群轨迹检查后才参与平均。平均曲线在每个相位对本侧所有**入选且有关键点覆盖的周期轨迹**求算术平均，不把周期两端的遮挡外推值算进去。逐周期数值是该轨迹与**本侧平均曲线**的二维均方根距离；总体偏差汇总所有可比较周期的偏差，另列左右平均轨迹之间的距离。数值越小，表示这段视频里的轨迹重复性越高。

播放视频时会逐步画出当前周期及脚踝位置，已播放周期保留为细线，完整平均曲线为粗线；拖动进度条也会同步更新。鼠标悬停周期条目可突出对应曲线，点击条目可跳到视频中的对应位置。少于 3 帧有效关键点的周期仍会列出，但标为“无法绘制”；中间周期可见度低于 70%、相位覆盖不足或轨迹明显离群时，会标出排除原因；同侧不足 2 个入选周期时无法计算该侧偏差。点击“查看完整分析简报”可展开结论；结果页右上角的“导出 PDF 报告”可下载指标与曲线报告。

稳定性分级只是 Demo 中的经验提示，受拍摄角度、遮挡和着地事件检测影响；不能据此判断跑姿优劣或伤病风险。新分析会保存逐帧实际时间戳，用于可变帧率视频的骨架、曲线与播放进度同步。

### 分析历史与数据

浏览器界面产生的上传视频与结果默认保存在 `output/jobs/<任务 ID>/`，包括原视频 `source.<扩展名>` 和下述分析文件。设置 `PACE_DATA_DIR` 可更改 `output` 的位置。历史页可以查看已有结果；原视频仍在时可重新分析，新结果单独保存，不覆盖旧任务。旧任务保留原结果；在历史页点击“重新分析”可生成新版轨迹和 PDF，也可以点击“删除记录”清理某条历史及其上传视频、报告文件。分析进行中不能删除。

所有视频和摄像头画面都由当前服务处理。部署到远程服务器时，浏览器会把画面发送到该服务器。

## 命令行用法

### 跑步机视角校正对照实验

使用已有环境运行，不需要重新安装或下载另一套模型：

```bash
source .venv/bin/activate
python run_pipeline.py --input input.mp4 --output outputs/
```

输出 `2d_frames/frame_000001.json` 等 COCO 17 点像素坐标、分数与可见关键点范围 bbox，`keypoints_2d.npy`、身体中心归一化诊断数据、原始时间戳，以及 A 原始、B 仅平滑、C 仅固定坐标转换、D 坐标转换加平滑的四份三维数组。VideoPose3D 输入仍遵循官方图像归一化，不使用身体中心归一化替代。`comparison.mp4` 并排呈现二维叠加、原始三维和 D 结果，另输出 `rtmpose_2d.mp4`、`pose3d_raw.mp4`、`pose3d_corrected.mp4`、脚踝 XYZ 曲线及膝角对比图。

`quality_2d.json` 检查肩、髋、膝、踝的成对可见率及疑似跳点；可见率低于 70% 时保存二维视频并停止三维实验。人工检查二维视频后可用 `--allow-low-quality` 覆盖门槛。二维质量检查不能自动确认所有标签错误。

可选人工方向标记：

```bash
python calibrate.py --input input.mp4
```

点击跑步机后方、前方，再按 Enter 保存视频同目录的 `camera_config.json`；R 重选、Esc 取消。实验自动读取配置，也可显式传 `--camera-config path.json`。两个图像点用于估计前后轴正负，完整三维旋转仍来自全片肩、髋和躯干中位方向。它不是完整相机标定。世界坐标 X 为前后、Y 为向上、Z 为横向。地面平移为全片脚踝高度 5% 分位数，仅代表脚踝低位参考面，不能恢复真实跑带高度或根节点整体位移。

默认 Savitzky–Golay 窗口 11 帧、二阶；`--smooth-window 9` 可调，必须为奇数。对不均匀时间戳先重采样再滤波。`metrics.json` 保存骨长 CV、左右腿长度差、躯干倾斜、左右膝角、脚踝 XYZ/幅度/峰值速度和疑似交换、骨长异常帧。骨长和交换仅检测，不自动改写姿态。旋转前后膝角及骨长保持不变；时间平滑可能改变动作幅度，需要结合曲线比较。没有真实三维参考时，指标改善不能证明几何准确度提高。

```bash
python main.py input/test.mp4 --output output
```

输出包括：

- `player.mp4`：H.264 编码、可在浏览器中拖动播放的视频
- `annotated.mp4`：骨架、膝角、步频和步态事件叠加视频
- `landmarks.csv`：统一 33 槽位的原始值与平滑值（17 点模型缺失槽位为空）
- `metrics.json`：步频、步时、关节 ROM、左右差异、规则反馈和足部稳定性摘要
- `report.png`：指标 Dashboard、膝角曲线和足部轨迹
- `report.html`：可展开的简要文字报告
- `report.pdf`：关键指标、关节角度曲线、脚踝离地高度及平均轨迹
- `timeline.json`：逐帧骨架、角度、事件、时间戳，以及全部足部周期轨迹和偏差

## 部署到服务器

适用 Debian/Ubuntu Linux 服务器。服务器只需要能联网，并有一个可以执行 `sudo` 的用户。将本项目推送到 GitHub 后，完整部署流程只有下面三步：

```bash
git clone <你的 GitHub 仓库地址>
cd <仓库目录>
./deploy.sh
```

`deploy.sh` 会自动检查并安装 Docker/Compose（Debian/Ubuntu）、构建镜像、创建持久化数据卷、启动服务并等待健康检查。默认监听服务器的所有网卡，地址为 `http://服务器公网IP:8000`。云平台安全组与服务器防火墙需允许 TCP 8000。

需要改端口或上传上限时，复制配置示例再执行：

```bash
cp .env.example .env
# 编辑 .env，例如 PORT=8080
./deploy.sh
```

也可以只对本次执行覆盖配置：`PORT=8080 ./deploy.sh`。

分析历史和上传视频保存在 Docker 的 `pace_data` 卷中，容器重建后仍可读取。更新时进入项目目录，运行 `git pull && ./deploy.sh`。检查状态与日志可运行 `docker compose ps`、`docker compose logs -f pace-lab`。部署脚本会同时兼容新版 `docker compose` 和旧版 `docker-compose`。

直接通过 HTTP 和 IP 访问可使用视频上传分析；远程摄像头模式需要 HTTPS 域名。该 Demo 默认没有登录功能，公开部署时建议通过反向代理加 HTTPS 和访问控制。反向代理还需允许最大 2 GB 的上传请求。服务提供 `/healthz` 健康检查接口，并固定使用 1 个 Gunicorn worker 来保持任务状态一致。

不用 Docker 时也可以设置持久化目录并以单进程启动：

```bash
export PACE_DATA_DIR=/srv/pace-data
gunicorn --bind 127.0.0.1:8000 --workers 1 --threads 4 --timeout 300 app:app
```

## 拍摄建议

- 固定机位、完整侧面、全身入镜；尽量避免遮挡。
- 建议 720p 以上、约 30 FPS，至少包含多个完整步态周期。
- 二维单目视频无法提供实验室级三维运动学结果；输出仅供运动观察。
