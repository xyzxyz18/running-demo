# Running Pose Analysis Demo 实现说明

## 1. 项目目标

实现一个基于单目跑步视频的本地跑姿分析 Demo。

输入：

-   MP4 / MOV 等跑步视频
-   默认假设人物以侧面或接近侧面的视角跑步

输出：

1.  人体姿态关键点
2.  左右脚踝运动轨迹
3.  脚踝离地高度（Ankle Clearance）曲线
4.  Foot Strike（脚落地）时间
5.  Step / Stride 时间
6.  Cadence（步频）
7.  膝关节屈曲角度
8.  每次落地附近的膝关节形状
9.  一个完整支撑周期内的膝关节变化曲线
10. 平均跑步周期和标准差

第一版建议使用 **MediaPipe Pose** 替代
ViTPose。后面的轨迹处理、事件检测和关节分析可以采用相同的算法思想。

# 3. Pose 数据

## 3.1 使用的关键点

跑步分析核心只需要：

``` text
nose

left_hip
left_knee
left_ankle

right_hip
right_knee
right_ankle
```

如果使用 MediaPipe Pose，可以直接从 33 个 landmarks 中提取这些点。

每一帧保存：

``` python
{
    "frame": 100,
    "time": 3.333,
    "left_hip": [x, y, visibility],
    "left_knee": [x, y, visibility],
    "left_ankle": [x, y, visibility],
    "right_hip": [x, y, visibility],
    "right_knee": [x, y, visibility],
    "right_ankle": [x, y, visibility]
}
```

其中：

``` text
x ∈ [0, 1]
y ∈ [0, 1]
visibility ∈ [0, 1]
```

------------------------------------------------------------------------

# 4. 坐标系修正

## 4.1 为什么不能直接计算角度和距离

Pose 模型通常返回归一化坐标：

``` text
x = pixel_x / image_width
y = pixel_y / image_height
```

因此 x、y 的物理尺度不同。

例如视频：

``` text
1920 × 1080
```

同样的：

``` text
0.1
```

对应：

``` text
x: 192 px
y: 108 px
```

如果直接用：

``` python
sqrt(dx**2 + dy**2)
```

会产生宽高比导致的几何失真。

------------------------------------------------------------------------

## 4.2 Aspect Ratio Correction

定义：

``` python
aspect = image_width / image_height
```

将所有点转换成以图像高度为统一尺度：

``` python
x_corrected = x * aspect
y_corrected = y
```

即：

``` text
P = (x, y)

P' = (x * width / height, y)
```

之后所有：

-   距离
-   向量
-   角度

都使用修正后的坐标。

------------------------------------------------------------------------

# 5. 关键点质量控制

每个 landmark 都有 visibility。

首先过滤：

``` python
if visibility < VISIBILITY_THRESHOLD:
    point = invalid
```

推荐初始：

``` text
VISIBILITY_THRESHOLD = 0.5
```

实际开发时允许配置。

对于短时间缺失：

``` text
valid → invalid → valid
```

可以使用线性插值：

``` text
P(t) = P0 + α(P1 - P0)
```

其中：

``` text
α = (t - t0) / (t1 - t0)
```

如果连续缺失过长，则不要强行插值，应标记该区间为 invalid。

------------------------------------------------------------------------

# 6. Leg Length 估计

不能简单使用：

``` text
distance(hip, ankle)
```

因为跑步时膝盖会弯曲。

应该把腿分成：

``` text
Hip → Knee
Knee → Ankle
```

分别计算长度。

## 6.1 Thigh Length

每一帧：

``` python
thigh_length = distance(hip, knee)
```

对整个视频取中位数：

``` python
thigh = median(thigh_lengths)
```

## 6.2 Shank Length

每一帧：

``` python
shank_length = distance(knee, ankle)
```

同样取中位数：

``` python
shank = median(shank_lengths)
```

## 6.3 Leg Length

``` python
leg_length = thigh + shank
```

左右腿可以分别计算，也可以最终使用左右腿的平均值：

``` python
leg_length = (left_leg_length + right_leg_length) / 2
```

使用 median 而不是 mean，可以减少错误 Pose 对尺度估计的影响。

------------------------------------------------------------------------

# 7. Ankle Ground Level

目标是估计：

> 脚在支撑阶段最接近地面时的 ankle y。

因为图像坐标中：

``` text
y 越大 → 越靠下
```

所以可以使用整个视频 ankle y 的高分位数估计 ground level。

左右脚分别计算：

``` python
left_ground = percentile(left_ankle_y, 90)
right_ground = percentile(right_ankle_y, 90)
```

不要直接使用最大值，因为单帧错误 Pose 可能产生极端值。

------------------------------------------------------------------------

# 8. Ankle Clearance

定义：

``` text
clearance = (ground_y - ankle_y) / leg_length
```

注意：

``` text
ground_y > ankle_y
```

表示脚踝高于地面。

因此：

``` text
clearance ≈ 0
```

表示接近地面。

而：

``` text
clearance 越大
```

表示脚踝抬得越高。

左右脚分别产生：

``` text
left_clearance[t]
right_clearance[t]
```

最终形成时间序列：

``` text
time →
clearance

       /\          /\
      /  \        /  \
_____/    \______/    \____
```

------------------------------------------------------------------------

# 9. Clearance 信号平滑

原始 Pose 会产生：

-   单帧跳动
-   landmark jitter
-   遮挡造成的错误
-   左右脚识别短暂错误

因此需要：

``` text
原始信号
   ↓
缺失值插值
   ↓
Median Filter
   ↓
Moving Average
   ↓
平滑 Clearance
```

推荐：

``` python
median_filter(window=5)
moving_average(window=5)
```

参数应该做成配置项。

不要过度平滑，否则会影响 Foot Strike 的时间精度。

------------------------------------------------------------------------

# 10. Swing Peak Detection

为了识别真正的步态周期，需要先找到脚抬起的 swing peak。

简单找：

``` python
max(clearance)
```

不够鲁棒。

应该：

1.  找局部峰值
2.  对峰值高度进行筛选
3.  使用多个峰值的 median 估计典型 swing height

例如：

``` text
peaks = [0.31, 0.35, 0.34, 0.36, 0.91]
```

其中：

``` text
0.91
```

可能是错误 Pose。

使用 median：

``` text
typical_peak ≈ 0.35
```

------------------------------------------------------------------------

# 11. Foot Strike Detection

## 11.1 基本思想

Foot Strike 定义为：

> 脚踝从 swing 状态下降并穿过 contact threshold 的时刻。

定义：

``` python
contact_threshold = typical_peak * CONTACT_FRACTION
```

例如：

``` text
typical_peak = 0.40
CONTACT_FRACTION = 0.25

threshold = 0.10
```

信号：

``` text
clearance

       swing
        /\
       /  \
      /    \
-----●------  contact threshold
     ↑
  foot strike
```

------------------------------------------------------------------------

# 12. 防止重复检测

仅使用 threshold 会产生误检。

例如脚在地面附近抖动：

``` text
____/\/\____
```

可能产生多个 crossing。

因此必须加入时序约束。

## 12.1 Swing Height Constraint

一次 strike 之前必须出现足够高的 swing：

``` python
peak >= typical_peak * SWING_PEAK_FRACTION
```

否则不认为发生了新的步态周期。

## 12.2 Minimum Contact Duration

两次 crossing 之间必须存在最小 stance/contact 时间。

例如：

``` text
MIN_CONTACT_SECONDS = 0.05
```

过短的 crossing 忽略。

## 12.3 Minimum Strike Interval

相邻 strike 不能过近：

``` python
MIN_STRIKE_INTERVAL = 0.15
```

具体数值根据视频帧率和跑步速度调整。

------------------------------------------------------------------------

# 13. Strike 时间的亚帧插值

不要直接把 crossing 归到后一帧。

假设：

``` text
frame 30:
clearance = 0.12

frame 31:
clearance = 0.08

threshold = 0.10
```

threshold 位于两帧之间。

计算：

``` python
alpha = (threshold - value0) / (value1 - value0)
```

得到：

``` python
cross_frame = frame0 + alpha
```

时间：

``` python
cross_time = cross_frame / fps
```

这样可以提高 Foot Strike 时间精度。

------------------------------------------------------------------------

# 14. Step / Stride

对于每只脚：

``` text
Left:
L1 → L2 → L3 → L4

Right:
R1 → R2 → R3 → R4
```

不要只计算：

``` text
L → R
```

来估计 cadence。

而应该使用：

``` text
L1 → L2
R1 → R2
```

也就是同一只脚连续两次 strike 的时间间隔。

定义：

``` python
stride_time = next_same_foot_strike - current_strike
```

------------------------------------------------------------------------

# 15. Cadence

如果：

``` text
stride_time
```

单位是秒。

一个 stride 包含两个 steps，因此：

``` python
cadence = 120 / stride_time
```

如果平均 stride：

``` text
0.70 s
```

那么：

``` text
cadence = 120 / 0.70
        ≈ 171.4 steps/min
```

实际系统应该：

1.  收集多个 stride
2.  删除明显异常值
3.  使用 median 或 trimmed mean
4.  输出平均 cadence

例如：

``` json
{
    "cadence_spm": 171.4,
    "stride_time_s": 0.70
}
```

------------------------------------------------------------------------

# 16. Knee Flexion Angle

每一帧需要：

``` text
H = Hip
K = Knee
A = Ankle
```

构造：

``` text
v1 = H - K
v2 = A - K
```

计算夹角：

``` text
theta =
acos(
    dot(v1, v2)
    /
    (norm(v1) * norm(v2))
)
```

得到的是：

``` text
Hip-Knee-Ankle interior angle
```

为了让：

``` text
直腿 = 0°
```

定义：

``` python
knee_flexion = 180 - theta_degrees
```

因此：

``` text
腿完全伸直:
flexion ≈ 0°

腿弯曲:
flexion > 0°
```

------------------------------------------------------------------------

# 17. Knee Angle 的数值稳定性

计算 acos 前必须：

``` python
cos_theta = np.clip(cos_theta, -1.0, 1.0)
```

避免浮点误差造成：

``` text
acos(1.0000001)
```

产生 NaN。

同时，如果：

``` python
norm(v1) < epsilon
```

或者：

``` python
norm(v2) < epsilon
```

则这一帧角度无效。

------------------------------------------------------------------------

# 18. Foot Strike 附近的 Knee Analysis

不要简单：

``` python
knee_angle[strike_frame]
```

因为：

-   Pose 有抖动
-   strike 本身存在检测误差
-   膝角变化速度可能很快

应该在 strike 附近建立一个时间窗口。

例如：

``` text
strike - 0.10 s
        ↓
strike
        ↓
strike + 0.10 s
```

取得窗口内的：

``` text
knee_flexion(t)
```

然后寻找局部 minimum。

------------------------------------------------------------------------

# 19. 为什么寻找局部 Minimum

在脚触地附近，通常希望找到一个稳定的"接触附近膝关节形态"。

因此：

``` text
Foot Strike
      ↓
Local Knee Window
      ↓
Knee Flexion Curve
      ↓
Local Minimum
```

例如：

``` text
knee flexion

25° |       ●
20° |      / \
15° |  ●--●   ●
10° | /
 5° |
    +----------------
         strike
```

寻找窗口内局部最低点。

------------------------------------------------------------------------

# 20. Parabolic Sub-frame Fitting

不要只使用离散帧：

``` python
argmin(angle)
```

可以取最小值附近的几个点：

``` text
t-1
t
t+1
```

拟合：

``` text
y = a*x² + b*x + c
```

抛物线顶点：

``` text
x_vertex = -b / (2*a)
```

这个：

``` text
x_vertex
```

作为更加精确的 knee minimum 时间。

这样可以获得：

``` text
knee_time
knee_flexion
```

而不是只得到某一帧。

# 22. Knee Shape 可视化

## 22.1 每次 Strike 的腿形状

对于每次 Foot Strike：

``` text
Hip
 ↓
Knee
 ↓
Ankle
```

将 Hip 平移到固定原点：

``` python
hip = [0, 0]
knee = knee - original_hip
ankle = ankle - original_hip
```

这样不同 step 可以叠加。

结果类似：

``` text
          Knee
         / | \
        /  |  \
       /   |   \
      /    |    \
   Ankle  ...  Ankle
```

可以观察：

-   膝盖位置变化
-   小腿方向变化
-   单次动作是否出现异常离群姿态

------------------------------------------------------------------------

# 23. 不要直接平均 Knee / Ankle 坐标

不能简单：

``` python
mean(knee_positions)
mean(ankle_positions)
```

因为：

``` text
平均坐标 ≠ 平均姿态
```

应该：

1.  计算 thigh vector
2.  计算 shank vector
3.  对方向进行统计
4.  对 thigh / shank 长度使用 median
5.  根据平均方向 + 典型长度重新构造平均腿

这样可以得到更加稳定的平均 Knee Shape。

------------------------------------------------------------------------

# 24. 支撑期 Knee Shape

将每个 stride / stance 归一化为：

``` text
0% ───────────────────── 100%
strike                 toe-off
```

然后在固定时间比例采样：

``` text
0%
25%
50%
75%
100%
```

每个时间点计算：

``` text
Hip
Knee
Ankle
```

得到：

``` text
t = 0%:
H0 K0 A0

t = 25%:
H1 K1 A1

...

t = 100%:
H4 K4 A4
```

这样可以绘制整个支撑阶段的平均腿形状变化。

------------------------------------------------------------------------

# 25. Knee Flexion Curve

对于每个 stance：

``` text
strike → toe-off
```

将时间归一化到：

``` text
0 → 1
```

然后插值到统一的采样点：

``` text
0%, 5%, 10%, ..., 100%
```

每个 step 得到：

``` text
[angle_0, angle_5, ..., angle_100]
```

多个 step：

``` text
step1 = [...]
step2 = [...]
step3 = [...]
...
```

堆叠：

``` python
matrix = np.array(all_steps)
```

计算：

``` python
mean_curve = matrix.mean(axis=0)
std_curve = matrix.std(axis=0)
```

最后画：

``` text
Knee Flexion
    ↑
    │          /\
    │         /  \
    │   _____/    \_____
    │
    └────────────────────→
      0%              100%
          Stance %
```

并绘制：

``` text
mean ± std
```

形成 variability band。
